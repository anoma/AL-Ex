#+TITLE: Source Retention Plan
#+STARTUP: content

* Status

Ready for implementation review.

This plan records the source-retention design agreed on 2026-08-24. It
supersedes the initial screenshot plan where this document differs from it.
The current transaction identifier is valid for mutating evaluations. A
concurrency probe confirmed that 12 competing transactions committed unique,
monotonic identifiers. The feature does not need a new transaction allocator.

* Goal

Retain the exact text supplied through a runtime source entry point. Return the
exact authored text for a durable class or method clause. Keep the existing
=AL.Source= decompiler as the fallback for package and macro definitions that
have no retained text.

The first consumer is the read-only Glamorous Toolkit class and clause view.
Editing, save, delete, move, and compile-time macro capture are separate work.

* Contract

Add this public entry point:

#+BEGIN_SRC elixir
AL.eval_source(text, branch \\ AL.Branch.head(), opts \\ [])
#+END_SRC

The entry point accepts a raw UTF-8 string containing one or more AL surface
forms. It parses and lowers outside Mnesia. It evaluates all forms as one AL
program in one Mnesia transaction. The transaction has one =tx_id=, as current
=AL.eval/4= does.

The entry point retains source only when the input contains at least one direct
source-bearing definition:

- a top-level =defmethod=;
- a top-level =defclass=;
- a =defmethod= directly inside a retained =defclass=.

Other AL goals can occur in the same input. Input with no source-bearing
definition still evaluates, but creates no retained source record. This rule
avoids assigning durable source identity to read-only evaluations, which do not
advance =system_time=.

Parser, lowering, provenance, or AL execution failure leaves no source rows.
Return structured errors. Do not use =Code.string_to_quoted!/2= for editor
input.

* Transaction identity

=AL.eval/4= reads =AL.Command.system_time(branch)= inside its outer Mnesia
transaction. The first durable command takes a write lock on the same counter,
increments it, and uses the old value as its command timestamp. Mnesia retries
a competing transaction. Mutating evaluations therefore commit unique,
monotonic =tx_id= values. The identifiers are not contiguous by transaction
because a multi-command transaction advances =system_time= more than once.

Keep a regression test with concurrent mutating evaluations. Do not use the
same guarantee for read-only evaluations.

* Durable model

Create two branch-local durable tables owned by a new =AL.SourceStore= module.
They are an append-only source archive. They do not affect AL execution.
=AL.Command= remains authoritative for executable state. The source archive is
authoritative only for verbatim presentation.

** Source text

One row stores the complete input text once:

#+BEGIN_SRC elixir
{:source_text, tx_id, text, origin}
#+END_SRC

The branch is implicit in the table name, as it is for command and object
tables. =origin= is bounded metadata such as =%{kind: :eval_source, label: nil}=.
Do not require a file path.

** Source span

One row attaches an exact durable definition version to a range in the source
text:

#+BEGIN_SRC elixir
{:source_span, command_t, tx_id, kind, range, context}
#+END_SRC

=command_t= is the primary key. It is the exact command timestamp returned by
the defining durable write:

- a method clause uses the timestamp of its =set_oapply= command;
- a class uses the timestamp of the =set_class= command for the declared class.

=kind= is =:defmethod= or =:defclass=. =context= contains stable presentation
information:

#+BEGIN_SRC elixir
%{class: class, method: method_name, authored_as: :standalone | :nested}
#+END_SRC

Class context can omit =method=. Context is descriptive. Readers use
=command_t= as identity.

A range uses 1-based line and column positions with an exclusive end:

#+BEGIN_SRC elixir
%{
  start: %{line: line, column: column},
  stop: %{line: line, column: column}
}
#+END_SRC

Store the original text unchanged. Do not normalize line endings or formatting.
Do not store byte offsets in the first version.

* Parser and range policy

Create a pure parser component under =AL.Source=. Use:

#+BEGIN_SRC elixir
Code.string_to_quoted(text, columns: true, token_metadata: true)
#+END_SRC

Return a lowered program and a capture tree. The capture tree contains the
outer range for each top-level =defclass= and =defmethod= and a range for every
direct nested =defmethod= in a =defclass=.

Use the form's own =line= and =column= as the start. Use
=end_of_expression= as the exclusive end when present. Use the documented
=end= token metadata only through one tested fallback routine.

The first version starts at the =defclass= or =defmethod= token. It does not
claim leading comments or preceding blank lines. It retains comments and blank
lines inside the definition range. A later comment-ownership policy can use
=Code.string_to_quoted_with_comments/2=.

Implement one slicing function. Build a line index from the original binary.
Test its interpretation of parser columns. Preserve CRLF and UTF-8 exactly.
Reject a range that does not round-trip to the expected definition form.

Capture only direct definitions. Do not recursively treat a =defmethod= inside
an arbitrary conditional, loop, or method body as one retained declaration.
Such a form can execute zero, one, or many times and needs a different source
identity model.

* Exact provenance

Do not infer a source link after commit from names alone. Do not attach a span
only to ={tx_id, object, key}=. Retraction and redefinition can reuse logical
names and clause keys.

Assign one opaque =capture_id= to every captured definition before entering the
Mnesia transaction. Use ={evaluation_ref, ordinal}=, where =evaluation_ref= is a
fresh BEAM reference for this =eval_source= call and =ordinal= is the definition
position in the parsed input. Generate both outside the transaction so Mnesia
retries reuse the same IDs. Do not derive an ID from the class, method name,
clause key, or range. Two identical authored forms must have different IDs.

Use an explicit, ephemeral source reference during source-aware definition
execution:

#+BEGIN_SRC elixir
%AL.Source.Ref{
  capture_id: capture_id,
  tx_id: tx_id,
  kind: :defmethod,
  range: range,
  context: context
}
#+END_SRC

The normal =AL.Lowering.ast_to_pattern/1= path discards AST metadata. Keep that
path unchanged. Add source-aware lowering that binds each captured AST node to
its =capture_id= before metadata is lost.

A standalone definition becomes:

#+BEGIN_SRC elixir
%AL.Goal.SourceScope{capture_id: capture_id, goals: [lowered_definition]}
#+END_SRC

A source-aware =defclass= keeps its ordinary method order but encodes each
nested method as this closed, runtime-only term:

#+BEGIN_SRC elixir
{:al_source_method, capture_id, method_name, head, body}
#+END_SRC

Refactor the installed =:defclass= behavior to decode both its current
=[method_name, head, body]= entries and tagged entries through shared helpers.
The first pass decodes either shape and performs all existing method retractions.
The second pass calls ordinary =defmethod= directly for an ordinary entry. For a
tagged entry, it runs that same =defmethod= call inside =SourceScope= with the
entry's ID. Keep the existing two-pass order. Do not create a separate class
construction or method accretion implementation. Position and ID remain paired
when two tagged entries have identical selector, head, and body values.

Register =SourceScope= as an internal goal form so the =:defclass= bootstrap
behavior can store a symbolic scope goal whose ID is an AL variable. The actual
={evaluation_ref, ordinal}= value exists only in the running input and its
transaction-local capture registry.

Add a source-scope stack to =AL.Choicepoint= and =AL.Continuation=. Copy it in
every choicepoint and continuation constructor, including =OApply=, =Call=,
control-flow alternatives, and backtracking paths. When =continue/1= returns
through a continuation, restore the stack from that continuation. Refactor
=collect_all_solutions/4= to accept the stack and seed each sub-search root with
it, so =forall=, =findall=, and related control flow do not lose the active scope.

Interpreting =SourceScope= pushes its ID, splices its goals followed by an
internal scope-exit goal, and then resumes normal interpretation. The exit goal
restores the previous stack. Choicepoints created inside the scope contain both
the active stack and the pending exit goal. Nested method scopes therefore
restore the outer class scope on success and backtracking. Do not use the
process dictionary.

Add =AL.Goal.validate_storable/1= and call it before every command argument or
method body reaches durable storage. It must recursively inspect recognized and
unknown structs, proper and improper lists, tuples, and maps. Reject a concrete
capture ID, =:al_source_method= term, or internal scope-exit goal at any depth.
=AL.Goal.to_stored/1= must return a typed error for these values instead of using
its generic fallback. A symbolic =SourceScope= in the trusted bootstrap body is
valid because its ID is an AL variable. No concrete ID or nested tag may occur
in an =AL.Command= or =AL.Object= row.

=AL.Interp.Store.write/3= already receives the exact command timestamp from
=AL.Command=. Extend the source-aware write path as follows:

1. Write the ordinary command.
2. Update the ordinary object projection.
3. Read the active =capture_id= from the current choicepoint.
4. If its registry reference matches the defining write, write one
   =source_span= row with that command timestamp and record that anchor for the
   ID.
5. Return the updated AL state.

For a method reference, only =set_oapply= is defining. For a class reference,
only =set_class= for the declared class object is defining. Validate the object
against the resolved reference context. Nested method scopes override the outer
class scope.

At successful transaction finalization, require every =capture_id= to have
exactly one defining command timestamp. Abort with a typed provenance condition
if an ID is missing or receives more than one anchor. This prevents a plausible
but incorrect source link.

* Evaluation transaction

Refactor =AL.eval/4= so =AL.eval_source/3= does not wrap a completed evaluation
with a second write transaction.

Use one internal transaction runner. It accepts the lowered program and an
optional source capture. Inside the same transaction it:

1. reads the current =tx_id=;
2. writes =source_text= when the capture tree is non-empty;
3. evaluates the program;
4. writes =source_span= rows from exact defining commands;
5. validates complete one-to-one provenance;
6. commits the result or aborts all executable and source writes together.

Keep existing =AL.eval/4= behavior and return shape unchanged. Preserve the
heap-limited execution path.

* Branch lifecycle

=AL.SourceStore= follows the same branch lifecycle as the command store.

- =AL.Command.setup/0= or application setup creates source tables for =:main=.
- =AL.Branch.setup/0= ensures source tables exist for every known branch.
- =AL.Branch.create_fork/3= creates the destination tables and copies source
  data through the same command cutoff.
- Copy only =source_span= rows whose =command_t= is at or before the copied
  command cutoff.
- Copy only =source_text= rows referenced by copied spans.
- A prefix fork that ends inside a transaction can retain a subset of that
  transaction's spans. The complete raw text remains valid for each surviving
  span.
- =AL.Branch.discard/1= drops the source tables.
- =fork_fresh= starts without inherited source, then records source submitted
  on that branch.

Existing stores receive empty source tables. Do not backfill decompiled text as
if it were verbatim source. Missing source is a normal legacy state.

* Readers

Do not change the tuple shapes of =AL.Object.scan_method/4= or
=AL.Object.scan_oapply/5=. Existing callers depend on them.

Add explicit provenance-preserving readers:

#+BEGIN_SRC elixir
AL.Object.scan_open_class_versions(...)
AL.Object.scan_open_method_versions(...)
AL.Object.scan_open_oapply_versions(...)
AL.Object.scan_class_history(...)
AL.Object.scan_method_history(...)
AL.Object.scan_oapply_history(...)
#+END_SRC

The open readers return only rows whose =tx_to= is =:open=. The history readers
can return closed and requested versions. All version rows include =tx_from= and
=tx_to= with the existing data. The oapply clause row's =tx_from= is the exact
=set_oapply= =command_t= used by =source_span=. Do not use the method row's
=tx_from= for clause source.

Add retained-source readers under =AL.Source=. The low-level method reader
performs:

1. read the open or explicitly requested oapply clause version;
2. use that clause's =tx_from= to read =source_span=;
3. use the span's =tx_id= to read =source_text=;
4. slice the original text with the stored range;
5. return the exact text, source start line, and origin metadata.

Expose a display adapter with one stable result map:

#+BEGIN_SRC elixir
%{
  text: text,
  start_line: positive_integer,
  provenance: :retained | :decompiled,
  origin: origin | nil,
  authored_as: :standalone | :nested | nil,
  diagnostic: nil | term()
}
#+END_SRC

For retained text, =start_line= is =range.start.line=. If no span exists, use
the current =AL.Source.defmethod_source/4= decompiler, set =start_line= to =1=,
and set =provenance= to =:decompiled=. Treat this absence as a normal legacy
state. A span without its text, an invalid range, or a mismatched kind is a
diagnostic error. The display adapter records the diagnostic and returns the
decompiled fallback with =start_line: 1=.

A nested method returns the exact nested shorthand that the user wrote. It is
valid for display but is not independently evaluable outside its =defclass=
context. Record =authored_as: :nested= so future save support can restore that
context.

* Glamorous Toolkit integration

Change GT reads only after the Elixir reader is complete.

=ALClassCoder>>functionEntries= must use the open version readers. It must not
show closed historical method or clause rows. For each open oapply row, request
source with that row's =tx_from=. Return bridge rows with this exact shape:

#+BEGIN_SRC elixir
[name, seq, result.text, length(head), result.start_line,
 result.provenance, result.diagnostic]
#+END_SRC

Map every row field into the =BeamFunctionEntry= dictionary:

#+BEGIN_SRC text
name -> row[0]
seq -> row[1]
source -> row[2]
arity -> row[3]
start -> row[4]
sourceProvenance -> row[5]
sourceDiagnostic -> row[6]
#+END_SRC

Use =seq= only for clause ordering. Use the retained transaction-local start
line or the decompiler fallback line =1= instead of fabricating =seq + 1=.

Add =sourceProvenance= and =sourceDiagnostic= state to =ALClauseCoder= and load
it in =refreshFromEntry:=. When the diagnostic is non-nil, show a read-only
warning above that clause's decompiled fallback. Include the diagnostic term and
identify the source as decompiled. Do not hide the clause source.

Keep =ALClauseCoder>>saveFunction=, move, and delete disabled. Exact readback
must not imply that editing semantics are complete.

* Implementation phases

** Phase 1: Pure parser

- Add structured parser errors.
- Extract top-level and nested ranges.
- Add exact slicing and round-trip checks.
- Test Unicode, CRLF, tabs, comments, blank lines, one-line forms, nested
  blocks, malformed defclass bodies, and multiple top-level forms.

** Phase 2: Durable source store

- Add branch-local source tables.
- Add create, copy-prefix, and drop operations.
- Add migration-safe setup for existing stores.
- Test tip forks, empty forks, prefix forks, discard, and restart.

** Phase 3: Transaction runner

- Refactor =AL.eval/4= around one internal transaction runner.
- Add =AL.eval_source/3=.
- Store raw text in the same transaction.
- Add a concurrent transaction-ID regression test.
- Test parser failure, AL failure, and provenance failure rollback.

** Phase 4: Method provenance

- Add =SourceScope= and scope stacks to choicepoints and continuations.
- Propagate scope through calls, alternatives, backtracking, and sub-search roots.
- Add deep durable-value validation for all term containers.
- Add source-aware =defmethod= execution without changing normal macro calls.
- Attach the exact =set_oapply= command timestamp.
- Add open version and explicit history readers.
- Test new methods, appended clauses, repeated identical source forms, nested
  calls, sub-searches, backtracking scope restoration, retractions, and
  redefinitions.

** Phase 5: Class provenance

- Refactor the existing two-pass =:defclass= behavior to decode ordinary and
  tagged method entries through shared helpers.
- Carry one distinct =capture_id= per nested method, including identical entries.
- Preserve class construction, category import, the complete retract pass, and
  multi-clause selector behavior.
- Test nested shorthand, repeated selectors, duplicate nested forms, redef,
  categories, and multiple classes in one input.

** Phase 6: Read-only GT source

- Return the stable display result and line metadata through the bridge.
- Enumerate only open method and clause versions.
- Map start, provenance, and diagnostic fields into each =BeamFunctionEntry=.
- Keep per-clause decompiler fallback at line =1=.
- Show corruption diagnostics above the fallback source.
- Leave save, delete, and move for a later design.

* Required verification

Run focused source tests, then:

#+BEGIN_SRC sh
mix format
mix format --check-formatted
mix compile --warnings-as-errors
epmd -daemon
mix test
mix dialyzer
#+END_SRC

For isolated runs, use a fresh =AL_MNESIA_DIR= with
=AL_MNESIA_DISTRIBUTED=false=.

The source test matrix must include:

- concurrent mutating evaluations have distinct =tx_id= values;
- read-only source input creates no retained source row;
- all source and executable writes roll back together;
- two definitions in one transaction share one raw text row;
- duplicate and redefined clauses map to distinct =command_t= values;
- identical standalone and nested forms keep distinct =capture_id= scopes;
- scope survives =OApply= and =Call= continuations, alternatives, =forall= and
  =findall= sub-searches, backtracking, and failure;
- no concrete capture ID, nested tag, or scope-exit goal survives deep storage
  validation inside a list, improper list, tuple, map, or struct;
- nested methods map to their own spans;
- GT enumerates only open clause versions and uses the oapply =tx_from=;
- GT maps retained start lines, provenance, and corruption diagnostics;
- legacy macro definitions decompile with =start_line: 1=;
- branch tip and prefix copies keep only valid source anchors;
- restart preserves retained text;
- malformed or missing source data is reported;
- exact slices preserve comments inside the range, whitespace, UTF-8, and line
  endings.
  endings.

* Decisions deferred

The following items are not part of this feature:

- compile-time source capture for existing =defclass= and =defmethod= macros;
- leading-comment ownership;
- byte-offset storage;
- source deduplication or compression;
- GT save, delete, move, and reorder;
- file watching and external file identity;
- source retention for dynamically executed declarations inside arbitrary AL
  control flow;
- valid-time source queries.
